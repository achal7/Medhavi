# Promise Module Implementation Plan

## Overview
This plan outlines the implementation of the Promise/ATP (Available to Promise) module for the Medhāvī ProductionPlanning system. The Promise module is responsible for real-time order promising with tiered SLAs (<1s for Simple ATP, <5s for Standard CTP, <30s for Full CTP).

**Leveraging Existing Work**: There is existing code in the `.ignore/Promise` directory that provides a solid architectural foundation. This plan will reuse applicable components while addressing gaps and ensuring alignment with the PDD specifications.

## Current State
Based on Phase-Management.md:
- Phases 0-4 (Wave 1) are completed: Foundational Shared Core, Integration & Ingest, Material Availability Query, Material Reservations, Routing & Process Master Data
- Phases 5-8 (Wave 2) show varying status: Capacity CTP Module (verify implementation status), Transport ATP Module (verify implementation status), Postgres/Marten Repository Integration, Promise/ATP Orchestrator

The Promise module depends on:
- Material Availability (completed)
- Material Reservations (completed)
- Capacity CTP (verify current implementation status - user indicates new features implemented)
- Transport ATP (verify current implementation status)
- Routing & Process Master Data (completed)

**Note**: User mentioned new features implemented in capacity area. Need to verify exact status of Capacity CTP and Transport ATP modules to determine what stub/mock work is actually needed.

**Existing Code Review**: There is existing code in `.ignore/Promise` directory that provides a good architectural foundation for the Promise module. However, it has some gaps:
1. The `checkCapacity` function in Steps.fs is incomplete (just returns empty values)
2. The CapacityProviders interface in Providers.fs doesn't match the PDD-specified Capacity CTP interface (uses GetBuckets/GetQtyDuration vs CheckCapacity)
3. Missing confidence intervals (p50/p85/p95) in PromiseResponse as specified in PDD
4. Some placeholder implementations that need completion

**Code Reusability Assessment**:
- **Reusable**: Policy handling (PromisePolicy.fs), core types (Types.fs), FX handling (CostFx.fs), scoring logic (Scoring.fs), orchestrator structure (Orchestration.fs, Service.fs), pipeline steps concept (Steps.fs)
- **Needs Completion**: Capacity checking implementation (Steps.fs checkCapacity function), transport options processing, reservation creation logic
- **Needs Alignment**: Capacity provider interface to match PDD-specified Capacity CTP CheckCapacity interface
- **Missing Features**: Confidence intervals (p50/p85/p95) in promise response

## Core Components to Implement

### 1. Domain Types and Interfaces
Define F# types for:
- Promise request/response models
- Routing selection results
- Promise limiter types
- Confidence intervals (p50/p85/p95)
- Cost calculation components

### 2. Routing Selection Service
Implement:
- RoutingProvider interface
- Primary and alternate routing selection
- Work routing and transport routing extraction

### 3. Material ATP Service
Implement:
- Material availability checking using MaterialProvider
- Net available calculation: onHand + inbound - reservations - safety
- Supplier fallback options for shortfalls

### 4. Capacity ATP Service
Implement or verify:
- CapacityCTP interface implementation
- If existing implementation exists: verify completeness for Promise module needs
- If gaps exist: implement missing components
- Capacity checking based on routing steps
- Earliest feasible window calculation

### 5. Transport ATP Service
Implement or verify:
- TransportATP interface implementation
- If existing implementation exists: verify completeness for Promise module needs
- If gaps exist: implement missing components
- Transport itinerary options
- Leg capacity, schedule, and constraint checking

### 6. Promise Orchestrator
Implement the main process flow:
1. Routing Selection (FIRST!)
2. Material ATP
3. Capacity ATP (using work routing from step 1)
4. Transport ATP (using transport routing from step 1)
5. Calculate Promise Date (max of materialReady, capacityReady, transportArrival)
6. Create Tentative Reservations (material, capacity, transport)
7. Return Promise Response with:
   - Decision (Accepted/Rejected)
   - Promise Date (if accepted)
   - Limiter (if rejected)
   - Cost, Confidence, Reservations

### 7. Reservation Creation
Implement:
- Tentative reservation creation across all three domains
- Rollback mechanism on failure
- Reservation ID generation

### 8. Policy and SLA Handling
Implement:
- Core policy presets (Gold/Silver/Bronze)
- Priority/full-order/full-delivery enforcement
- Risk/confidence scoring
- Tiered SLA handling (<1s/<5s/<30s)

## Data Flow
```
Customer Order (Product, Quantity, Due Date)
        ↓
Routing Selection → Primary Routing + Alternates
        ↓
Material ATP → MaterialReady Date
        ↓
Capacity ATP (using work routing from step 1) → CapacityReady Date
        ↓
Transport ATP (using transport routing from step 1) → TransportArrival Date
        ↓
Promise Date = MAX(MaterialReady, CapacityReady, TransportArrival)
        ↓
Create Tentative Reservations (if all available)
        ↓
Return Promise Response
```

**Note**: Verify that Capacity ATP and Transport ATP implementations actually exist and are complete before assuming they can be used directly. May need to implement missing components or create temporary stubs.
